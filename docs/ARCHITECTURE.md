# Architecture

CodexDictate is an `LSUIElement` AppKit application whose menu and lifecycle are coordinated by `AppDelegate`. SwiftUI supplies the Settings and HUD content, while AppKit supplies `NSStatusItem`, a non-activating `NSPanel`, pasteboard access, and application targeting.

`DictationController` is the `@MainActor` orchestration boundary. A pure `DictationStateMachine` enforces the single-pipeline phases `idle`, `recording`, `finalizingAudio`, `transcribing`, `structuring`, `inserting`, `completed`, `cancelled`, and `failed`. Modifier-edge monitors feed a `HotKeyTogglePolicy`: Control + Option toggles recording, while Option alone during recording stops, pastes, and submits with Return. Processing presses are rejected without overlapping work.

`AudioRecorderService` writes mono AAC to a dedicated temporary directory, exposes metering, preserves duration with a monotonic clock, and stops automatically after eight minutes. Startup and termination cleanup remove abandoned files. `TargetApplicationService` captures the frontmost PID/bundle plus exact Accessibility window and editable-element references at press time. Before insertion it restores and revalidates both the original window and editor. `PasteService` writes the complete result to the pasteboard, sends Command+V, and optionally sends Return after a settling delay. The result intentionally remains on the clipboard because macOS does not acknowledge whether a Chromium/Electron editor consumed the synthetic paste; this makes a missed event recoverable.

`KeychainService` owns a non-synchronizing generic-password item. `SettingsStore` persists only non-secret preferences. `OpenAIClient` uses an ephemeral injected transport, typed errors, centralized models, redaction-safe logging, one bounded transient retry, and one retry for an empty transcription response. `TranscriptionService` builds multipart audio requests.

Prompt transformation is a typed, fidelity-first pipeline whose in-memory document keeps five distinct values: unchanged `rawTranscript`, conservative `normalizedTranscript`, atomic `semanticUnits`, user-facing `structuredPrompt`, and independent `verificationResult`.

1. `TranscriptChunker` partitions long raw input without dropping or overlapping characters. Each chunk is normalized independently with semantic summarization forbidden.
2. A separate inventory request maps each raw/normalized chunk into typed `SemanticUnit` values. Inventories are merged and assigned stable unit identifiers.
3. The generator produces either a conservatively cleaned request or an adaptive Codex prompt from the merged inventory only.
4. A separate verifier compares the raw transcript, normalized transcript, full inventory, and generated prompt. `DeterministicFidelityVerifier` additionally checks protected paths, URLs, repositories, dates, names, labels, identifiers, versions, numbers, acronyms, negations/modal terms, and empty sections.
5. Failed verification supplies exact findings to a targeted repair request and reverifies. There are at most two repair attempts.
6. Any stage error, malformed/incomplete structured response, empty output, or repeated fidelity failure returns exactly `DICTATED REQUEST:\n\n<raw transcript>`.

The Responses API requests strict JSON Schema through `text.format`, retain `gpt-5.6-terra` with low reasoning, and use input-sized output budgets from 8,192 through 32,768 tokens rather than the former fixed 4,096-token ceiling. An incomplete or malformed structured response is retried once. Only `final_prompt` or the raw fallback reaches insertion; semantic inventories and verifier diagnostics remain internal and are never logged.

`DiagnosticStore` keeps a typed ring buffer for the five most recent sessions. It records only local operational metadata: phase/stage timing, request attempts and HTTP statuses, output sizes, fidelity result counts, stop gesture, target/focus decisions, clipboard writes, and synthesized key-event posting. The user can copy a pretty-printed JSON export from Settings or the menu. The buffer is never written to disk or transmitted, and error values are reduced to fixed codes. It cannot contain API keys, headers, audio, audio paths, raw/normalized transcripts, generated prompts, clipboard text, document contents, or window titles.

No transcript or result is written to disk. Only the latest raw and processed strings are held in memory until termination. The application currently has one prompt-generation route: automatic post-transcription formatting; failed-audio retry re-enters that same route from the newly recovered raw transcript. There is no separate manual restructure action to bypass the source-of-truth service. There is no telemetry, remotely collected analytics, backend, extension, broad keyboard event tap, or third-party runtime dependency.
